# DEVLOG System Guide

## What is it?

A lightweight session logging system for S8 Professor.
Each dev session gets one entry in `DEVLOG.md` — auto-generated by Claude, committed to git.

**Files:**
```
DEVLOG.md                        ← The log itself (newest entry first)
.claude/commands/devlog.md       ← /devlog slash command definition
.claude/DEVLOG-GUIDE.md          ← This file
```

---

## Usage

At the **end of every dev session**, run:

```
/devlog
```

Claude will:
1. Check `git log` and `git diff` for context
2. Ask you one question: *"What did you accomplish this session?"*
3. Generate a structured entry
4. Prepend it to `DEVLOG.md`
5. Stage + commit automatically
6. Show confirmation

---

## Entry Format

```markdown
## [2026-03-27] — Short session title

**Duration:** ~2h
**Branch:** feat/mobile-match-list

### Done
- Built match list screen with Supabase data fetching
- Implemented free/premium gate (first 3 analyses free)
- Fixed RevenueCat sandbox purchase flow

### Blockers
- None

### Next
1. Add analysis detail screen
2. Wire coupon generation to backend
3. Test on physical device (Android)

### Commit
`feat: add match list screen with free/premium gate`
```

## Git Workflow

The `/devlog` command commits only `DEVLOG.md`. Your feature commits and the devlog commit stay separate:

```
git log --oneline

abc1234  chore: update devlog — mobile match list session     ← /devlog commit
def5678  feat: add match list screen with free/premium gate  ← your work
...
```

This keeps feature history clean and devlog updates traceable.

---

## Manual Entry (without /devlog)

Copy the template from the top of `DEVLOG.md` and fill it in manually, then:

```bash
git add DEVLOG.md
git commit -m "chore: update devlog — <session title>"
```

---

## Reading at Session Start

At the start of a new session, read the latest entry in `DEVLOG.md` to pick up where you left off. The **Next** section tells you exactly what to work on.

You can also prompt Claude:

```
DEVLOG.md'yi oku ve nerede kaldığımızı özetle.
```

---

## Example Session Flow

```
1. Session start:
   → Read DEVLOG.md → "Next" section shows priorities
   → Start working

2. During session:
   → Normal git commits for features/fixes

3. Session end:
   → /devlog
   → Answer: "Mobile match list ekledim, Supabase'den veri çekiyor"
   → Claude generates entry, commits DEVLOG.md
   → Done
```

## Commit Type Reference

| Prefix   | When to use                        |
|----------|------------------------------------|
| `feat`   | New feature added                  |
| `fix`    | Bug fixed                          |
| `chore`  | Config, tooling, dependencies      |
| `refactor` | Code restructure, no behavior change |
| `docs`   | Documentation only                 |
| `test`   | Tests added or fixed               |
| `style`  | Formatting, no logic change        |
